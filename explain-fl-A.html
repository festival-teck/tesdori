問1第1章 テストの基礎シラバス 1.1ID 1-11
テストについて、正しい記述はどれか。
  1. A　テストとは、ソフトウェアを実行して実際の結果を期待結果と比較するテスト実行の活動を指し、レビューは含まれない
  2. B　テストの目的は指定された要件を満たすかの検証であり、ニーズを満たすかの確認は受け入れ時の承認作業として扱う
  3. C　テストには検証だけでなく、ユーザーやステークホルダーのニーズを満たすかの妥当性確認も含まれる
  4. D　テストは技術的な活動なので、計画や見積り、モニタリングはテストに含めず、プロジェクトマネジメントで扱う
解答と解説
正解：C　テストには検証だけでなく、ユーザーやステークホルダーのニーズを満たすかの妥当性確認も含まれる
「テストはテスト実行だけ（静的テストは含まない）」「テストは検証だけ」はどちらもよくある誤解。テストには静的テストも含まれ、検証と妥当性確認の両方が含まれる。また、計画・マネジメント・見積り・モニタリング・コントロールもテストに必要な活動である。

問2第1章 テストの基礎シラバス 1.1.2ID 1-14
静的テストで欠陥が見つかった場合のデバッグについて、正しい記述はどれか。
  1. A　動的テストの場合と同じく、まず故障を再現し、診断によって原因の欠陥を特定してから修正する
  2. B　欠陥が直接見つかっているので、故障の再現や診断は不要で、デバッグは欠陥の除去になる
  3. C　静的テストで見つかった欠陥は、修正の前に動的テストで故障を発生させ、欠陥であることを確認する
  4. D　静的テストで見つかった欠陥はデバッグの対象にならず、レビューのフォローアップとして作成者が対応する
解答と解説
正解：B　欠陥が直接見つかっているので、故障の再現や診断は不要で、デバッグは欠陥の除去になる
静的テストは欠陥を直接発見するもので、故障を引き起こすわけではない。そのため再現や診断は必要なく、デバッグは欠陥を取り除くことになる。

問3第1章 テストの基礎シラバス 1.2.3ID 1-02
締め切りに追われていた開発担当者が仕様を読み違え、割引条件を誤ってコーディングした。リリース後、利用者の画面に誤った請求額が表示された。
このとき「利用者の画面に誤った請求額が表示されたこと」は次のどれに当たるか。
  1. A　エラー
  2. B　根本原因
  3. C　故障
  4. D　欠陥
解答と解説
正解：C　故障
人が誤りを犯すことがエラー（仕様の読み違え）、その結果コードに埋め込まれたものが欠陥（誤った割引条件）、欠陥が実行されてシステムが期待通りに動かないことが故障（誤った請求額の表示）。締め切りのプレッシャーのように、問題が起きた根底の理由は根本原因として扱われる。
この問題の誤りを報告する（新しいタブ）
問4第1章 テストの基礎シラバス 1.3ID 1-04
指定された要件をすべて徹底的にテストし、見つかった欠陥もすべて修正した。しかしリリースしたシステムは利用者の業務に合わず、ほとんど使われなかった。この状況に最も関係するテストの原則はどれか。
  1. A　早期テストで時間とコストを節約
  2. B　「欠陥ゼロ」の落とし穴
  3. C　テストはコンテキスト次第
  4. D　テストは欠陥があることは示せるが、欠陥がないことは示せない
解答と解説
正解：B　「欠陥ゼロ」の落とし穴
検証（仕様通りか）だけでは、利用者のニーズや期待を満たすシステムになるとは限らない、というのが「欠陥ゼロ」の落とし穴。検証に加えて妥当性確認（ニーズを満たすか）も行う必要がある。

問6第1章 テストの基礎シラバス 1.4.1ID 1-32

  1. A　テスト活動は論理的な順番に従い、前の活動が完了してから次の活動を開始するのが原則である
  2. B　多くの活動は論理的にはシーケンシャルに見えるが、イテレーティブまたは並行して実施されることが多い
