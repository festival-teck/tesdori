問1第1章 テストの基礎シラバス 1.1.2ID 1-01
シラバスが示す典型的なデバッグの流れとして、正しいものはどれか。
  1. A　静的解析 → レビュー → 作業成果物の修正
  2. B　テスト設計 → テスト実行 → 欠陥レポートの作成
  3. C　故障の再現 → 診断（根本原因の発見） → 原因の修正
  4. D　確認テスト → リグレッションテスト → 欠陥レポートのクローズ
解答と解説
正解：C　故障の再現 → 診断（根本原因の発見） → 原因の修正
デバッグは、テストで見つかった故障の原因（欠陥）を見つけて取り除く活動で、典型的には「再現 → 診断 → 修正」の流れになる。確認テストやリグレッションテストはデバッグの後に行うテスト活動であり、デバッグそのものではない。なお静的テストで見つかった欠陥は直接見つかっているため、再現や診断は不要。

問2第1章 テストの基礎シラバス 1.2.2ID 1-07
テストと品質保証（QA）の関係について、正しい記述はどれか。
  1. A　テスト結果はQCでの欠陥修正に使われるが、QAのプロセス改善には使われない
  2. B　QAはプロダクト指向の是正アプローチであり、主にテストチームが責任を持つ
  3. C　テストはQCの一形式であり、QCはプロダクト指向の是正アプローチである
  4. D　テストはQAの主要な形式であり、QAはプロセス指向の予防的アプローチである
解答と解説
正解：C　テストはQCの一形式であり、QCはプロダクト指向の是正アプローチである
テストはQCの主要な形式で、QCはプロダクト指向の是正アプローチ。QAはプロセス指向の予防的アプローチで、プロジェクトに参加するすべての人が責任を持つ。テスト結果はQCでは欠陥の修正に、QAではプロセスがうまくいっているかのフィードバックに使われる。

問3第1章 テストの基礎シラバス 1.3ID 1-03
あるチームは、毎回まったく同じ手動リグレッションテストを変更せずに繰り返してきた。最近はこのテストで新しい欠陥がほとんど見つからない。この現象を最もよく表すテストの原則はどれか。
  1. A　テストの弱化
  2. B　「欠陥ゼロ」の落とし穴
  3. C　全数テストは不可能
  4. D　欠陥の偏在
解答と解説
正解：A　テストの弱化
同じテストを繰り返すと新しい欠陥を見つける効果が薄れていく、というのが「テストの弱化」。対策として、テストやテストデータを変更したり新しいテストを作ったりする。ただし自動化したリグレッションテストのように、同じテストの繰り返しに価値がある場合もある。

問4第1章 テストの基礎シラバス 1.4.1ID 1-05
テスト活動のうち、テストベースを分析して「何をテストするか」という問いに答える活動はどれか。
  1. A　テスト実装
  2. B　テスト分析
  3. C　テストのモニタリングとコントロール
  4. D　テスト設計

テスト分析では、テストベースを分析してテスト可能なフィーチャーを識別し、テスト条件を定義して優先順位を付ける。これが「何をテストするか」。テスト設計はテスト条件をテストケースなどに落とし込む活動で、「どのようにテストするか」に答える。テストのモニタリングとコントロールは、テストの進捗を確認し、必要な是正処置をとる活動。
