問1第1章 テストの基礎シラバス 1.1ID 1-36
テストという活動の性質について、シラバスの記述に合っているものはどれか。
  1. A　テストは技術的な活動であり、計画・見積り・モニタリングなどのマネジメントは含まれない
  2. B　テストは大部分が知的活動であり、専門知識、分析スキル、批判的思考やシステム思考が求められる
  3. C　テストで最も重視されるのは、定められた手順を正確かつ速く実行するための作業スキルである
  4. D　テストは、手順書とツールさえあれば誰が行っても同じ結果が得られる機械的な作業が中心である
解答と解説
正解：B　テストは大部分が知的活動であり、専門知識、分析スキル、批判的思考やシステム思考が求められる
シラバスは、テストは大部分が知的活動であり、専門知識を持ち、分析スキルを使い、批判的思考やシステム思考を適用することが求められるとしている。また、テストは技術的な活動だけでなく、計画・マネジメント・見積り・モニタリング・コントロールも必要。

問2第1章 テストの基礎シラバス 1.1.1ID 1-35
テストの目的が異なることがある要因として、シラバスで挙げられているものの組み合わせはどれか。
  1. A　テスト対象、テストレベル、テスト担当者の資格、テストツールのライセンス形態
  2. B　テスト技法、テスト自動化の度合い、カバレッジの度合い、テストドキュメントの詳細度
  3. C　テスト対象、テストレベル、リスク、従うSDLCモデル、ビジネスコンテキスト
  4. D　開発チームの規模、テスト担当者の経験年数、テスト環境の台数、テストツールの価格
解答と解説
正解：C　テスト対象、テストレベル、リスク、従うSDLCモデル、ビジネスコンテキスト
テストの目的は、テスト対象、テストレベル、リスク、SDLCモデル、そして企業構造・競争上の考慮事項・市場投入までの時間といったビジネスコンテキストの要因によって異なることがある。選択肢Bに挙げたテスト技法・自動化の度合い・カバレッジ・ドキュメントの詳細度は、テストのコンテキストの要因から影響を受ける事柄であり、テストの目的が異なる要因として挙げられているものではない。

問3第1章 テストの基礎シラバス 1.2.1ID 1-37
テスト担当者がプロジェクトの中で「ユーザーの視点」を提供する意義について、シラバスの記述に合っているものはどれか。
  1. A　代表的なユーザーの関与は通常不可能なため、テスト担当者がユーザーのニーズが考慮されていることを確認する
  2. B　代表的な複数のユーザーをプロジェクトに常時参加させるのが一般的なので、テスト担当者がユーザー視点を持つ必要はない
  3. C　テスト担当者は、ユーザーのニーズよりも、開発担当者の設計意図どおりに実装されていることの確認に専念する
  4. D　ユーザーのニーズの確認は受け入れテストの段階で行うものであり、それまでの開発ライフサイクルでは扱わない
解答と解説
正解：A　代表的なユーザーの関与は通常不可能なため、テスト担当者がユーザーのニーズが考慮されていることを確認する
テストは、開発プロジェクトにおいて間接的にユーザーの立場を代弁する手段となる。テスト担当者は開発ライフサイクルを通じて、ユーザーのニーズが理解され考慮されていることを確認する。代表的なユーザーの関与は、コストが高く適切なユーザーを確保できないため通常不可能とされている。

問4第1章 テストの基礎シラバス 1.2.3ID 1-38
欠陥について、シラバスの記述に合っているものはどれか。
  1. A　要件仕様書の欠陥は、実装段階で開発担当者が気づいて修正するため、後の工程には影響しにくい
  2. B　欠陥はソースコードで見つかるものであり、要件仕様書などのドキュメントからは発見できない
  3. C　SDLC初期の作業成果物の欠陥は、検出されなければ、後半の欠陥のある作業成果物につながることが多い
  4. D　欠陥を含むコードが実行されると、どのような状況であっても常に故障を引き起こす
解答と解説
正解：C　SDLC初期の作業成果物の欠陥は、検出されなければ、後半の欠陥のある作業成果物につながることが多い
欠陥は要件仕様書やテストスクリプトのようなドキュメント、ソースコード、ビルドファイルのような補助的な作業成果物からも発見できる。初期の作業成果物の欠陥は、見逃されると後半の欠陥につながる。欠陥の中には、実行すると常に故障になるものもあれば、特定の状況でしか故障にならないものや、故障にまったくつながらないものもある。

問7第1章 テストの基礎シラバス 1.4.5ID 1-42
アジャイルソフトウェア開発におけるテストマネジメントをする役割について、シラバスの記述に合っているものはどれか。
  1. A　アジャイル開発ではテストマネジメントのタスクは存在せず、各開発担当者が自分のテストを個別に判断する
  2. B　タスクの一部をアジャイルチームが担い、複数チームにまたがるタスクはチーム外のテストマネージャーが行うことがある
  3. C　独立性を保つため、1人がテストをする役割とテストマネジメントをする役割を同時に担うことはできない

問13第2章 ソフトウェア開発ライフサイクル全体を通してのテストシラバス 2.2.2ID 2-31
非機能テストについて、正しい記述はどれか。
  1. A　非機能テストは、すべての機能が完成したライフサイクルの最終段階でしか実施できない
  2. B　非機能テストは機能テストと同じテスト環境で実施するため、特殊な環境は必要ない
  3. C　多くの非機能テストのテストケースは、機能テストのテストケースから導出される
  4. D　非機能の欠陥は、発見が遅れても機能の欠陥より修正の影響範囲が小さいことが多い

テストツールについて、シラバスの記述に合っているものはどれか。
  1. A　表計算ソフトのように、テストのコンテキストではテストツールになるものもある
  2. B　テストツールの主な対象はテスト実行であり、テスト設計やマネジメントは対象外である
  3. C　テスト目的で開発・販売されているソフトウェアだけが、テストツールとして扱われる
  4. D　コラボレーションツールは開発用のツールであり、テストツールの分類には含まれない
解答と解説
正解：A　表計算ソフトのように、テストのコンテキストではテストツールになるものもある
シラバスは、その他のテストを補助するツールの例として、テストのコンテキストではテストツールになる表計算ソフトを挙げている。テストツールは実行だけでなく、マネジメント、静的テスト、設計・実装、非機能テスト、DevOps、コラボレーションなど多くの活動を支援する。

問40第6章 テストツールシラバス 6.2ID 6-11
テスト自動化の潜在的な利点として、シラバスで挙げられているものはどれか。
  1. A　ツールベンダーのサポートが継続されるため、ツールの保守や移行の負担がなくなる
  2. B　ツールに判断を任せられるため、テスト担当者の批判的思考が必要なくなる
  3. C　カバレッジなど評価の客観性が向上し、人間には複雑すぎる尺度を提供できる
  4. D　開発プラットフォームとの互換性がツールによって確保され、移行の手間がなくなる
解答と解説
正解：C　カバレッジなど評価の客観性が向上し、人間には複雑すぎる尺度を提供できる
評価の客観性の向上と、人間が導き出すには複雑すぎる尺度の提供は利点の1つ。ベンダーの廃業やサポート不足、人の批判的思考を軽視するほどのツールへの過剰な依存、開発プラットフォームとの非互換はリスクとして挙げられている。
